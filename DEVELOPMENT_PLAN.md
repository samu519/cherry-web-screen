## Current limits
The layout platform now restores registered widget instances, migrates and validates versioned documents, supports JSON import/export and recovery, and provides display profiles, grid/freeform modes and clean display mode. See [LAYOUTS.md](LAYOUTS.md) for usage and verification.

The shared visual pass now covers widget surfaces, control icons, theme-aware text, readable media artwork overlays, settings panels and editor controls. Dark/light dashboard and editor screenshots are generated by the browser suite. Physical touch verification remains pending; use [TOUCH_VALIDATION.md](TOUCH_VALIDATION.md) on the real display.

Browser control preferences remain local UI state. The Tauri Windows provider reads CPU/RAM, discovers optional WMI sensors, controls available audio endpoints/radios and reads the active media session. Unsupported features stay disabled; cooling, DDC/CI brightness, No molestar, network scanning and pairing remain pending. See [NATIVE.md](NATIVE.md) for setup, the bridge contract and verification limits. Physical touch hardware and manual OS actions still need validation.

Run regression checks with npm test. Serve locally with python -m http.server 8000 and open http://localhost:8000. The existing npm run tauri dev command launches the native shell when Rust and platform prerequisites are installed.

Run browser interaction checks with `npm run test:browser` after `npm install`. The suite uses installed Chrome on Windows, or Playwright Chromium (`npx playwright install chromium`). Set `CHERRY_BROWSER_PATH` to use another Chromium executable. It starts and stops its own local server and writes a 480 × 1920 screenshot to the system temporary directory.
